## 要解决的问题

价格监控不仅需要抓取网页价格，还需要处理商品配置、定时执行、通知、历史结果和运行控制。

如果所有逻辑都放在 scraper 中，随着功能增加，自动化逻辑和应用逻辑会越来越难维护。

## 可选方案

- **A.** 全部使用 C# + Playwright for .NET。
- **B.** 全部使用 Python + Playwright。
- **C.** ASP.NET Core 负责应用编排，Python + Playwright 负责浏览器自动化。

## 方案权衡

**A** 技术栈统一，部署和维护更简单，但应用逻辑和自动化逻辑会集中在同一个技术栈中。

**B** 自动化开发简单直接，但随着配置、调度、通知和运行管理增加，需要更仔细地维护应用结构。

**C** 可以让应用层和自动化层保持清晰边界，但增加了跨进程通信、错误处理和运行环境管理的复杂度。

最终选择 **C**，让 ASP.NET Core 管理应用工作流，让 Python 专注浏览器自动化。

## 潜在风险

外部网站的页面结构、价格格式和网络状态可能发生变化。

Python 进程也可能出现超时、异常退出或并发执行的问题，因此系统加入数据验证、异常价格检测、诊断日志和并发控制。

## 成功指标

- 定时任务能够稳定执行。
- 异常数据和 scraper 失败能够被发现。
- 多次运行不会产生冲突。
- 网站发生变化时，修改可以尽量限制在自动化层，而不会影响整个应用。
