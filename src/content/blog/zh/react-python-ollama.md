## 要解决的问题

应用需要让 React 前端与语言模型交互，同时避免把模型调用、Prompt 和 AI 相关逻辑直接放在前端。

还需要一个适合开发阶段的模型运行方式，方便快速测试不同 Prompt 和交互行为。

## 可选方案

- **A.** React 前端直接调用模型服务。
- **B.** 使用 Python 作为 AI 服务层，并连接托管的语言模型 API。
- **C.** 使用 Python 作为 AI 服务层，同时通过 Ollama 在本地运行语言模型。

## 方案权衡

**A** 架构最简单，但前端会直接依赖模型接口，AI 逻辑和界面逻辑容易耦合，也不利于隐藏模型相关配置。

**B** 可以保持清晰的前后端边界，并使用托管模型获得更稳定的服务，但开发和测试过程会依赖外部 API。

**C** 同样保持前端和 AI 逻辑分离，同时可以在本地快速测试 Prompt、模型和交互流程，但需要本地运行环境，并且模型能力受到本地硬件限制。

最终选择 **C**，在开发阶段使用 React + Python + Ollama，让模型实验保持灵活，同时避免前端直接依赖具体模型。

## 潜在风险

本地模型的性能和响应速度取决于运行设备，不同模型对内存和计算资源的要求也不同。

如果后续切换到托管模型或其他供应商，模型接口和响应格式可能发生变化，因此需要避免让这些细节扩散到前端。

## 成功指标

- React 前端只负责用户交互，不直接依赖具体语言模型。
- Python 服务能够独立处理 Prompt、模型调用和响应转换。
- 开发阶段可以通过 Ollama 快速更换和测试本地模型。
- 未来切换模型或托管服务时，前端不需要进行大规模修改。
